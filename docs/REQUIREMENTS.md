# 요구사항

## 1. 목적과 설계 상태

MigraFlow는 로컬 및 원격 파일 이전을 실행 인스턴스에서 제어하며, 중단 후 안전하게 이어서 실행하고 완료를 검증할 수 있어야 한다. 작성일은 2026-10-13이다. 이번 요청의 요구사항은 확정이며, 수치 정책·지원 OS·메타데이터 세부 범위는 제안 또는 확인 필요 사항이다.

## 2. 확정 요구사항과 수용 기준

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| R01 | NAS → NAS 중계 인스턴스 | 데이터가 중계를 경유하며, 중계에 전체 데이터 사본 없이 복사한다. DB·로그·임시 상태 저장량을 측정한다. |
| R02 | Python CLI/CUI + Rich | 비대화형 명령과 대화형 상태 화면이 같은 작업 엔진을 사용한다. 터미널 종료 후에도 영속 상태로 재개할 수 있다. |
| R03 | rsync 스트리밍 전송 | 제한된 배치로 전송하고 stdout 파이프를 파일 스트림으로 취급하지 않는다. 실제 NAS에서 연결 단절·부분 전송을 검증한다. |
| R04 | SQLite WAL | 로컬 디스크 DB에서 상태와 이벤트를 트랜잭션으로 기록하며 작업 중 동시 상태 조회가 가능하다. |
| R05 | 체크포인트·재시도·재개 | 프로세스 강제 종료와 네트워크 단절 후 완료 파일을 재사용하고 불확실한 파일은 재검증한다. 누락·중복 완료 처리가 없다. |
| R05a | 재개 사전 검사의 상태 일관성 | 원본 변경·누락을 감지해 재개를 차단하면 VERIFY_FAILED를 저장하고 이전 파일 검증 상태와 해시를 무효화한다. 대상 파일은 수정하지 않는다. |
| R04a | 상태 조회 집계 일관성 | 목록/파일 결과 변경과 진행 집계를 함께 커밋·롤백한다. 증분 삭제 후보의 저장된 통계는 기준 또는 현재 목록 변경 시 무효화한다. 구형 DB의 읽기 전용 조회는 DB를 변경하지 않는다. |
| R06 | 내용 해시 검증 | 기본 SHA-256이며 설정으로 MD5를 선택할 수 있다. 안정된 소스 세대와 대상의 파일별 해시를 동일 알고리즘으로 비교한다. 1바이트 변조를 탐지하며 검증 실패가 있으면 완료 승격을 막는다. |
| R07 | 100만~1000만 파일, 10TB 미만 | 전체 목록을 메모리에 적재하지 않는다. 단계별 규모 시험으로 메모리·DB 크기·IO·처리시간을 측정한다. |
| R08 | 소스 read-only | endpoint에 맞는 읽기 전용 마운트 또는 쓰기 권한 없는 계정을 사용한다. 이전 전후 소스의 내용·크기·mtime·권한이 바뀌지 않는다. atime 영향은 마운트/스냅샷 정책으로 별도 확인한다. |
| R09 | 증분 동기화 | 신규·변경 파일을 반영한다. 삭제·이름 변경·전송 중 변경을 구분하며 삭제는 기본 비활성화한다. |
| R10 | 모니터링 | 단계·처리량·건수·바이트·오류·재시도·검증·마지막 체크포인트를 CLI와 Rich 화면으로 조회한다. |
| R11 | 단계별 프로토콜 확장 | 첫 rsync 경로를 검증한 다음 기능 협상·계약 테스트를 갖춘 추가 전송 경로를 도입한다. |
| R12 | 안전한 cutover | 쓰기 동결, 최종 증분, 전체 최종 검증, 명시 승인과 롤백 계획 없이는 전환 준비 완료로 표시하지 않는다. |

출발지·목적지 각각의 local 타입 지원은 추가 확정 요구사항(R13)이다. 로컬은 MigraFlow 실행 인스턴스의 파일시스템 경로이며 다른 PC 경로는 원격이다. WSL2 실행 시 local은 WSL2가 접근하는 경로 기준으로, Windows 네이티브 지원 확정과는 별개다.

| 출발지 | 목적지 | 요구 동작 |
|---|---|---|
| 로컬 | 로컬 | 경로 간 복사·동기화 |
| 로컬 | 원격 | 업로드 |
| 원격 | 로컬 | 다운로드 |
| 원격 | 원격 | NAS 간 중계 |

모든 조합에 소스 무변경·증분·체크포인트·재시도·재개·SHA-256 검증과 동일/중첩 경로 차단을 적용한다. 로컬 대상의 공간·기존 파일 충돌도 검사한다. 이전은 복사·동기화이며 소스 자동 삭제는 추가하지 않는다.

첫 구현은 로컬 경로와 NAS 마운트 경로를 조합한다. 마운트 없는 rsync/SSH push/pull을 P2 범위로 추가했으며 한쪽은 local/mounted를 요구한다. 네트워크 마운트로 판별된 경로는 local 지정으로 마운트 정체성 검사를 우회하지 못하도록 명시적 마운트 정책을 요구한다. 로컬 소스도 읽기 전용 bind mount 또는 쓰기 권한 없는 실행 계정 등으로 보호를 검증한다.

TB는 우선 십진 단위(10^12 바이트)로 제안한다. TiB 여부는 운영 용량 산정 시 확인한다. 파일 수는 정규 파일 수와 디렉터리·링크 수를 구분해 집계한다. 처리량 SLA, RAM/CPU/디스크 예산은 미확정이며 벤치마크 전에 정해야 한다.

## 2.1. 현재 구현 범위

추가 사용자 요구: 기본 preflight는 목적지 쓰기 권한만 조회하며, 명시적 CLI 옵션 --test-destination-write로 실제 쓰기 시험을 수행한다. 구현 수용 기준은 기본/plan의 대상 무쓰기, 목적지 루트의 고유 임시 파일 생성·기록·flush·fsync·삭제, 소스 및 기존 대상 파일 보존, 오류·일반 중단 시 정리 시도, 삭제 실패 경로와 비정상 종료 코드 보고다. 권한 조회와 실제 시험 결과를 구분하며 성공을 전송/cutover 준비 완료로 해석하지 않는다. 옵션은 preflight 전용이며 YAML에는 추가하지 않는다. 실제 NAS 권한 검증은 해당 환경에서 별도로 수행해야 한다.

사용자 요청에 따라 SHA-256 기본값과 MD5 선택을 지원한다. verification.algorithm의 허용 값은 sha256/md5이고 생략하면 sha256이다. 알고리즘을 계획·검증 결과에 기록하며 변경하면 이전 해시를 새 알고리즘의 검증 근거로 재사용하지 않는다. MD5 선택은 약한 충돌 저항성을 가진 정책임을 결과에 표시한다.

사용자 요청에 따라 YAML 설정 파일과 CLI 옵션을 함께 지원한다. 파일 이름은 migration.local.yml이며 --config로 변경한다. 명령어 옵션이 YAML보다 우선한다. 현재 지원 키·명령과 경로 해석은 README에 기록한다.

D1 계획·저장·조회와 local/mounted 양쪽 조합의 실제 rsync 전송 및 SHA-256/MD5 전체 파일 검증을 구현했다. 전송·검증 재개, 제한 자동 재시도와 --baseline 새 회차의 동일 파일 재복사 방지를 지원한다. mounted는 Linux Python 실행 환경에서만 지원하며 실제 NAS 호환성·단절은 미검증이다. 스캔 재개, 대상 전용 항목 전체 조사와 선택적 POSIX 메타데이터 보존을 구현했다. 전체 NAS 메타데이터 호환성과 100만~1000만 파일 규모는 미검증이다. R01~R13의 전체 수용 기준을 달성한 상태로 해석하지 않는다. 계획의 PLANNED는 전송·cutover 준비 완료가 아니다. run은 저장 계획을 지정하고 자동 전체 검증하며 verify는 해당 전송을 다시 검증한다. VERIFIED는 계획에 포함된 파일 내용·크기·mtime와 디렉터리 존재·mtime가 일치했다는 의미다. 소스 스냅샷은 외부 운영 절차이며 VERIFIED 자체로 전체 미러 또는 cutover 준비 완료를 의미하지 않는다. POSIX 정책은 계획 항목의 ACL/xattr도 검증하고 추가 항목 조사는 별도 cutover-check가 수행한다.

실행은 소스 read-only 마운트를 기본 요구한다. 격리된 개발용 로컬 경로만 --allow-unprotected-source로 예외를 명시할 수 있으며 기록에 남긴다. 기존 대상 파일은 복구 수단과 계획 검토 후 --overwrite로 허용한다. Windows는 WSL rsync, Linux는 로컬 rsync를 사용한다.

## 2.2. 재개·재시도 수용 범위

같은 계획 ID의 전송/검증 중단과 강제 종료는 resume으로 계속한다. 배치별 검증 완료를 커밋하고 현재 양측 해시와 원본 세대를 재확인한 파일은 재복사하지 않는다. DB 커밋 전에 게시된 파일도 해시가 같으면 완료로 복구한다. 대상 변조/누락은 작업의 교체 권한 범위에서 복구하고, 원본 또는 알고리즘 변경은 새 계획을 요구한다.

retry.max_attempts의 기본값은 3(최초 시도 포함)이며 지수 백오프와 상한을 적용한다. 알려진 일시 rsync/OS IO·해시 읽기 오류만 재시도하고 권한·공간·정책·원본 변경·해시 불일치는 자동 재시도하지 않는다. 시도와 오류·대기 시간을 DB에 기록하며 수동 resume은 새 예산으로 시작한다.

부모 프로그램의 강제 종료 시 감시 장치가 rsync를 종료·회수하며, worker lease가 남아 있으면 재개 쓰기를 차단한다. 실제 Windows+WSL 및 Linux 강제 종료 시험에서 500개 검증 파일의 재복사 방지와 부분 파일 보존·재개를 확인한다. 스캔 재개는 로컬 회귀 시험으로 확인했다. 실제 NAS 연결 장애·분산 조정·전원 장애 전체 환경 검증은 후속 범위다.

## 2.3. NAS 마운트 전송 수용 범위

Linux에서 local→mounted, mounted→local, mounted→mounted의 run/resume/verify를 지원한다. mounted endpoint는 mount_source와 현재 마운트 테이블이 일치해야 하며 소스는 읽기 전용 보호, 대상은 쓰기 가능한 마운트가 필요하다. Windows Python의 UNC/네트워크 드라이브 지원은 추가하지 않는다. Windows 사용자는 Linux/WSL 안에서 Python과 NAS 마운트를 함께 사용한다.

마운트 누락·다른 공유·계획 이후 mount ID/옵션 변경을 차단한다. 전송 중 마운트 테이블을 폴링하고 rsync의 루트를 디렉터리 FD로 고정해 해제된 마운트 밑의 로컬 디렉터리에 쓰지 않도록 한다. 해시 읽기 전후와 재시도·재개에서도 마운트를 검사한다. 마운트 유지 상태의 일시 오류만 기존 재시도 정책을 적용하며 remount는 같은 공유라도 새 계획을 요구한다. NAS 동일 공유의 같은/중첩 상대 경로를 별도 mount로 노출해도 차단한다. 다른 export 이름·서버 별칭으로 노출된 동일 저장소를 자동 식별하지 못하므로 운영 환경에서 경로 분리를 확인한다.

검증 수용 기준은 세 방향×NFS/CIFS 모의 정체성×SHA-256/MD5의 실제 rsync 복사·중단·재개·양측 해시·변조 복구, 소스 내용/mtime/모드 보존, 마운트 변경 중 쓰기 중지다. 이는 실제 NAS 서버·커널 네트워크 IO 시험을 대체하지 않는다. NAS의 mtime 정밀도가 불충분하면 검증을 실패시키고 자동으로 완화하지 않는다. 실제 NAS 단절·재연결·권한·rename·inode 안정성 및 대규모 검증은 후속 작업이다.

## 2.4. 새 회차 증분 수용 범위

같은 endpoint/state/hash 정책의 VERIFIED 계획을 명시적인 --baseline으로 선택해 새 인벤토리와 회차를 생성한다. 신규·메타데이터 변경·기준 경로·대상 누락을 분류하고, 실행 때 기준의 검증 완료 경로에 한해 현재 양측 전체 해시/세대를 비교한다. 크기·mtime가 같아도 내용을 다시 확인하며 같으면 복사를 생략한다. 새 기준에 없는 기존 대상 경로는 자동 재사용하지 않는다. 내용 차이가 있는 기존 대상 교체에는 새 회차의 --overwrite가 필요하고 이전 승인을 승계하지 않는다. 대상 누락/신규는 전송하고 마지막에는 새 목록의 전체 내용·메타데이터를 검증한다.

기준과 새 회차의 파일/해시/상태는 별도로 저장한다. DB 준비·전송·검증 중 중단은 새 회차 ID의 resume으로 이어가며 소스 세대나 알고리즘 변경은 현재 회차 재개를 중지한다. 현재 양측 해시를 다시 읽으므로 복사를 생략해도 읽기 IO는 발생한다. 선택적 metadata-only skip은 제공하지 않는다.

전체 스캔이 성공하고 BLOCKED가 없을 때만 이전 목록에서 누락된 파일/디렉터리를 삭제 후보로 확정한다. 파일명 변경은 새 경로와 기존 경로 보존으로 처리하며 실제 삭제하지 않는다. 수용 시험은 SHA-256/MD5에서 변경/신규만 rsync 인자로 전달되는지, 동일 대상 inode 보존, 같은 size/mtime 변경 탐지, 삭제/이름 변경 보존, 기준 정책·정체성/상태 불일치 차단, 중단·부분 seed 복구, 다중 배치와 모의 NAS 조합이다. 실제 NAS·원자적인 snapshot·모든 메타데이터·대규모 성능은 별도 검증이다.

## 3. 최초 이전과 증분

최초 스캔은 포함·제외 정책에 따라 인벤토리를 만든다. 각 실행 회차에 scan epoch를 부여하고, 스캔이 온전히 끝난 경우만 누락 항목을 삭제 후보로 계산한다. 불완전 스캔은 완료 보고와 삭제 동기화의 근거가 될 수 없다.

증분의 기본 변경 후보는 상대 경로·종류·크기·mtime_ns다. 시간 정밀도 차이를 정규화하되 크기와 시간이 같다는 이유만으로 무결성이 검증됐다고 판단하지 않는다. 최종 검증은 설정된 내용 해시 알고리즘(기본 SHA-256, 선택 MD5)으로 수행한다. 이름 변경은 처음에는 삭제 후보와 신규 파일로 처리하는 단순 모델을 제안한다.

MigraFlow의 소스 접근은 read-only여도 서비스 쓰기는 계속될 수 있다. 이전 중 변경된 파일은 해당 세대의 검증을 폐기하고 재스캔한다. 서비스 일관성이 필요한 여러 파일은 같은 스냅샷 또는 쓰기 동결 범위로 묶는다.

## 4. 파일 및 메타데이터 정책

첫 구현의 제안 범위는 정규 파일·디렉터리·내용·상대 경로·mtime다. 빈 파일과 빈 디렉터리도 포함한다. 보존할 수 없는 속성은 사전 점검에서 표시한다.

ACL, 소유자/그룹, POSIX 모드, xattr, 하드링크, 심볼릭 링크, sparse 파일은 실제 NAS 조합에 따라 확인한다. 필수 속성의 손실은 실패로 처리한다. 장치·소켓·FIFO는 초기 미지원으로 보고하고 조용히 건너뛰지 않는다. 심볼릭 링크를 따라 소스/대상 루트 밖으로 접근하지 않는다.

대소문자 충돌, Unicode 정규화 충돌, 예약 이름, 경로 길이 제한, 시간 정밀도, 읽기 권한 실패는 전송 전에 보고한다. 원래 이름을 무단 변환하지 않는다. 명시 제외된 항목은 보고서에 남기고, 승인되지 않은 제외나 미지원 파일이 있으면 전체 이전 완료를 선언하지 않는다.

대상은 첫 구현에서 전용 이전 경로를 권장한다. 기존 파일 충돌·덮어쓰기 후보를 계획에 나타내고, 대상 스냅샷 또는 복구 수단을 확인한 후 실행한다. MigraFlow 상태·부분 파일과 운영 데이터는 분리한다.

## 5. 안전 및 실패 처리

- 소스/대상 루트, 실제 마운트 정체성, 경로 중첩, 여유 공간, 접근 권한을 실행·재개 때 점검한다.
- 대상 공간 부족이나 마운트 소실은 해당 작업을 정지한다. 로컬 마운트 포인트로 잘못 전송하지 않는다.
- 전송 오류, 읽기 실패, 사라진 파일, SHA 불일치, 정책 위반을 구분한다.
- 일시 오류만 제한 재시도하며, 영구 오류는 운영자의 조치 후 재개한다.
- rsync의 부분 성공/사라진 파일 종료 코드는 성공으로 치환하지 않고 회차를 불완전 처리한다.
- 소스 세대가 바뀌면 이전 전송·검증 결과를 새 세대의 성공으로 사용하지 않는다.
- 대상 삭제는 후보 보고·작업별 승인·대상 백업/스냅샷이 모두 있어야 한다.
- 대상과 소스의 경로·파일명도 민감정보일 수 있다. 로그 접근 권한과 보존 기간을 정한다.

## 6. 검증 및 완료 의미

전송 완료는 대상에 파일이 생성된 상태다. 검증 완료는 같은 안정된 소스 세대에 대해 내용 해시와 필수 메타데이터가 일치하는 상태다. 선택한 해시는 파일 내용 검증이며 ACL·디렉터리·링크 검증을 대체하지 않는다. 완료 보고서에 사용 알고리즘을 명시한다.

최종 전체 검증은 포함된 모든 정규 파일에 적용한다. 이미 검증한 결과는 스냅샷 식별자 등으로 소스 세대가 동일하고, 대상이 외부 쓰기로부터 보호되어 있다는 근거가 있을 때만 재사용한다. 근거가 없으면 다시 읽는다. 샘플링은 진행 진단용이며 전체 완료 판정의 대체 수단이 아니다.

완료 보고서에는 스냅샷/동결 식별, 파일 수·바이트 합계, 누락·추가·삭제 후보, 검증 불일치, 미지원 속성, 제외 정책, 실패 목록과 승인 기록을 포함한다. 실패 또는 미검증 파일이 하나라도 있으면 cutover 준비 완료로 판정하지 않는다.

## 7. 모니터링

현재 구현: run/resume/verify/cutover-check는 Rich 실시간 화면을 대화형 터미널에서 자동 제공하고 --live/--no-live로 제어한다. JSON과 비대화형 출력은 자동 화면을 사용하지 않는다. 작업 상태·경로·알고리즘, 전체 계획 파일/바이트, 커밋된 검증 체크포인트, 현재 단계 진행률·내용량·파일 평균/최근 처리량·ETA, 현재 해시 파일/읽기 바이트/속도, rsync 배치 참고 수치와 재사용·재시도·오류를 표시한다. 재시도 수는 저장된 누적 수로 시작하며 오류는 현재 실행의 표시 이벤트 수다. 현재 단계의 검증 성공/실패와 처리 건수를 구분한다. 별도 status --watch는 DB+WAL/상태 공간을 관찰하고 Ctrl+C로 감시만 종료한다. 스캔 화면·키보드 메뉴는 후속 범위다.

수용 기준은 화면 유무에 따른 파일·해시·DB 상태·종료 코드의 동일성, JSON 단일 결과 보존, Ctrl+C의 INTERRUPTED 기록, 표시 오류로 전송을 실패시키지 않기, 커밋 이후 체크포인트 반영과 제한된 로그/청크 메모리다. rsync 수치는 성공 판정에 사용하지 않고 실제 네트워크 바이트와 구분한다. 속도/ETA는 추정이며 미확정 단계·측정 전에는 값을 만들지 않는다. 화면 갱신 자체가 파일이나 DB에 쓰지 않고 전체 목록을 반복 조회하지 않는다. 아래 항목은 모니터링 전체 목표이며 모두 구현된 것은 아니다.

단계별 스캔/전송/검증 완료 건수, 실제 전송 바이트, 대상 검증 바이트, 평균·최근 처리량, 활성 배치, 재시도 수, 실패 수, 체크포인트 시간, DB/WAL 크기와 디스크 여유 공간을 표시한다.

전체 스캔 전에는 진행률 분모를 “미확정”으로 표시하고 ETA를 단정하지 않는다. 파일 수와 바이트 진행률을 구분한다. Rich 화면은 상태를 표시하며 화면 갱신 자체가 상태 저장을 수행하지 않는다.

## 8. cutover 요구사항

전환 단계는 준비 점검 → 서비스 쓰기 동결/스냅샷 확정 → 최종 증분 → 전체 검증 → 운영자 승인 → 연결 전환 → 서비스 검증이다.

서비스 중단 허용 시간, 전환 담당자, 연결 변경 방식, 허용할 롤백 기간을 사전에 기록한다. 새 NAS에서 쓰기가 시작된 뒤에는 구 NAS에 되돌리는 것만으로 롤백할 수 없다. 새 변경분의 역동기화 또는 복구 방식을 별도로 결정해야 한다. 구 NAS 원본은 승인된 보존 기간 동안 유지한다.

## 9. 범위 밖과 확인 필요

초기 범위 밖: 웹 대시보드, 다중 중계 분산 스케줄러, 양방향 동기화, NAS 내부 서비스 자동 설정, Windows 네이티브 전송 보장, 모든 메타데이터의 무조건 보존.

확인 필요: NAS/OS 버전, NFS/SMB/SSH/rsync 지원, 네트워크 경로와 대역폭, 스냅샷·ACL 요구, 운영 서비스의 쓰기 패턴, 파일 구성, RAM·로컬 SSD 예산, 대상 기존 데이터, 라이선스.

## 2.6. 추가 개선의 현재 수용 범위

사용자가 성능 개선과 스캔 재개·메타데이터 보존·전환 보고서·모니터링 확장을 모두 요청했다.

- 스캔 재개: plan --resume ID가 완료 디렉터리 재열거를 생략하고 미완료 디렉터리 부분 목록을 재작성한다. 원본 디렉터리 세대·기록 파일 크기/mtime·정체성·정책 변경과 구형 체크포인트를 차단한다. 상태만 기록하며 양측 데이터에 쓰지 않는다.
- 메타데이터: 기본 basic 계약을 유지한다. Linux 전용 posix는 계획 항목 mode·numeric UID/GID·POSIX ACL/xattr 보존과 검증을 추가한다. 원본 속성 변경·대상 변조를 탐지하며 권한·기능 부족을 성공으로 해석하지 않는다. endpoint 루트·NAS 고유 ACL·atime·링크는 별도 범위다.
- 감시: status --watch는 짧은 읽기 전용 스냅샷, 고정 작업 ID, 1~60초 간격, DB+WAL/상태 디스크 공간을 제공한다. 감시 종료는 작업 취소가 아니다. 실행 화면은 최근 최대 10초 처리율을 추가한다.
- 전환 점검: 같은 조정자 잠금에서 새 전체 검증·대상 추가 항목 조사를 수행하고 reports/report_extras에 저장한다. 읽기 전용 원본, 양측 동결, 복구 수단, 담당자 승인, 메타데이터 검토, 추가 항목 검토를 기록해야 READY다. 외부 증빙의 진위·강제 동결은 자동 검증하지 않으며 서비스 전환/삭제를 실행하지 않는다.
- 성능: fresh mountinfo와 파일/경로 안전 검사를 유지하면서 중복 조회·집계·정렬을 줄인다. 합성 표본의 시간·Python 할당량·DB 인덱스 비용을 기록한다. 실제 NAS와 백만 단위 수용 시험은 환경 준비 후 별도로 수행한다.

실제 NAS 환경은 미준비로 확인했다. [성능 근거](PERFORMANCE.md)와 [NAS 수용 시험](NAS_TESTING.md)을 구현 검증과 운영 검증의 경계로 사용한다.

## SSH push/pull 구현 범위 (2026-10-21)

사용자가 마운트 없는 SSH 직접 전송을 요청했다. Linux/WSL Python에서 local/mounted→rsync_ssh와 반대 방향을 구현하며 양쪽 SSH 직접 전송은 기존 P2 정책대로 차단한다. YAML/CLI의 host 별칭·절대 원격 경로·remote_state_dir를 지원하고 OS SSH 설정에서 키/agent 인증과 호스트 키를 검증한다. 자동 키 승인·비밀번호 프롬프트는 없다.

원격 Linux/Python 3.8+/rsync 3.1.3+/machine-id, 로컬 lease 디렉터리를 요구한다. 공통 상태 엔진에서 제한된 원격 목록, 전체 원격 해시, 증분/재개, POSIX 검증, 보고서를 처리한다. 원격 셸에는 고정 코드만 전달하고 원본에 helper를 업로드하지 않는다. 원격 root 고정·identity·worker lease와 source 무쓰기·기존 덮어쓰기·삭제 비활성화 정책을 유지한다. 상세 수용 시험과 실제 NAS 미검증 범위는 [SSH.md](SSH.md)를 따른다.

## 기능 검토 후 보강 수용 기준 (2026-10-21)

- 원격 lease와 양쪽 endpoint·조정자 state_dir의 동일/상위/하위·물리 경로 중첩을 데이터/lease 생성과 목적지 쓰기 시험보다 먼저 차단한다. 같은 서버의 반대 endpoint와 아직 없는 lease 하위 경로도 검사한다.
- YAML timeouts로 rsync IO 무진행 제한, 선택적인 배치 총 상한, SSH 원격 해시 읽기 무진행 제한, 선택적인 파일당 총 상한을 구분한다. 기본 총 상한은 없고 무진행 기본값은 1800초다. 진행 중 작업은 무진행 창보다 오래 실행될 수 있어야 하며 실제 정체·지정 총 상한에서는 실패/회수 후 안전하게 재개해야 한다. 로컬 해시 호출과 모든 로컬 파일시스템 정체에 적용되는 제한으로 해석하지 않는다.
- 원격 hash는 성공적으로 읽은 바이트 증가만 무진행 제한을 갱신한다. 중복 진행이나 불완전 응답으로 제한을 연장하지 않으며 최종 세대/전체 해시 검사를 유지한다. timeout 정책 변경은 기존 계획을 재사용할 수 있지만 데이터 정책 변경은 새 계획이 필요하다.
- 전환 보고서의 대기 디렉터리 조회는 인덱스를 사용하고 완료 행의 반복 전체 스캔을 피한다. 전체 추가 항목 저장·출력 샘플 제한·메모리 제한과 무삭제 계약을 유지한다. 합성 SQL 비용과 실제 NAS 성능을 구분한다.
